# Codex 参数写入实施计划

按用户要求，在已有读取功能上增加受控参数写入，保留现有人工操作。直接实施，不使用真实 MCU 验证。

- [x] 新增 AI写入设置：默认禁止；人工逐项允许变量并填写上下限，类型与实际大小必须匹配。权限只存在本次运行，重新连接/重置/烧录/加载配置时撤销。
- [x] MCP 增加 get_write_permissions、write_variable、get_write_result；写入参数为变量ID、十进制字符串值、预期旧值、唯一 request_key。重复相同请求只返回已有结果，不重发；不提供地址写入或探针控制工具。
- [x] 写入使用现有唯一 ProbeWorker，写前读取比较旧值、写后读回；结果区分排队、已验证、比较失败和写入后不确定，禁止自动重试。权限撤销使尚未执行的请求失效。
- [x] 限制本次进程256个操作记录、单一在途写入；记录请求、旧值/新值/读回及时间。MCP 请求总时限到期后不延迟执行。
- [x] 无硬件测试覆盖类型边界、非有限浮点、范围、默认禁用、重复提交、比较失败、取消、读回失败与并发拒绝；构建独立 dist/MemRW3-ai-enabled，不替换正在运行的只读程序。
- [x] 更新 Codex MCP 注册、说明与实际验证记录。本轮不调用真实写入，不暂停/复位/烧录或连接目标。

数值上下限由人工按机构/固件确认，本轮不臆测。写前比较并非 MCU 原子CAS；固件可能在比较与写入之间更新变量，读回仅证明该次读取一致。

实际结果：138项Rust、8项Python及三份配置检查通过；真实GUI仅检查默认写入关闭和工具清单，没有调用真实写入。详细交付见 Codex参数写入.md。
