# MemRW3 项目技术文档

## 1. 版本边界与来源

项目是 Rust 2024 桌面程序，基于 eframe/egui 和 probe-rs。增强版来自上游 v2.2.1，基准提交为 `c47c29403af1e1295403b415115a93de41f84f57`。仓库保留该提交及目标仓库原有初始提交的历史。

当前源码与 2026-10-20 Enhanced Pink 功能基线一致。2026-10-23 加入的源码可写缓冲、Keil 工程/Target 选择、后台编译任务及 F7/F8/全局 F5 绑定已撤回。原有 DebugEngine、硬件断点、栈帧及源码浏览功能继续存在。恢复操作保留本地弃用版本存档，但该存档不进入公共 Git。

## 3. 线程、硬件所有权与数据流

UI 主线程负责交互及渲染；唯一 ProbeWorker 串行执行连接、采集、变量/寄存器读写、烧录和调试命令。插件通过 `MemRWPlugin` 接口接收只读上下文，通过 `PluginAction` 请求副作用，不自行访问物理探针。

```text
Chart / Table / Debug
          │ PluginAction
          ▼
      MemRW3App ── ProbeCommand ──► ProbeWorker ──► ProbeSession / MCU
          ▲                             │
          └──── ProbeEvent / 调试快照 ────┤
Chart ◄── FrameData / RingBuffer ────────┤
Table ◄── LatestValue / RegisterData ────┘
```

`VariablePool` 根据绑定区分 Stream（Chart）和 Latest（Table）。同一轮相同物理地址可以合并读取，但 Chart 需要历史帧，Table 只需要最新值。ProbeSession 在连接期间复用 Core handle，避免热路径反复创建。

注意有两类缓冲：线程之间的有界 RingBuffer 用于搬运数据；Chart 自己的 `VecDeque<(f64, f64)>` 保存已摄取的历史。完整历史修改的是后者，不代表硬件到 UI 队列也无限扩展。极端负载下应检查实际速度与显示统计，不能把界面绘图性能当作硬件采样完整性的保证。

## 4. 完整曲线历史实现

### 4.1 容量语义

`src/ui/chart_plugin/legend.rs` 中 `buffer_size == 0` 表示完整保留。批量加入数据时不跳过旧样本，也不从队头驱逐；有限容量模式保留原有裁剪行为。

`SavedChartLegend.retain_all` 的 serde 默认值为 true，使缺少该字段的旧配置也采用完整历史。保存时记录这个选择。曲线属性对话框提供“保留全部采样”开关，暂停时可切回有限容量。

### 4.2 查看与绘制

“查看全部”恢复自动 X 范围与滚动。固定 X 轴和手动缩放只控制视口。`history_plot_points` 根据视口及像素宽度选择绘制点：保留首尾与区间极值，并维持时间顺序，以减少长记录逐点绘制开销。窄时间范围可以显示更细的原始细节。

该步骤只生成临时绘图数据，不改写保存的原始历史。游标、FFT 与 CSV 继续使用其相应的原始数据来源。数据量与内存没有被绘图压缩减少，因此仍需管理长时间采样的内存增长。

### 4.3 生命周期

全局暂停/继续保留历史；清空、重新加载配置及其他重建会话操作可能清除或重置数据。断开保留最后显示值，不能代替存档。程序退出后内存历史不保留。配置序列化不包含样本，CSV 是磁盘持久记录入口。

## 5. Watch 表格实现

`table_plugin/panel.rs` 负责列布局、搜索、操作与可选 SVD 面板；`tree.rs` 负责结构体/数组树节点、父子勾选和持久化。默认 Watch 占满宽度，按需启用 SVD。

列包括采集开关、名称、类型、地址、当前值、刷新频率、写入和操作。搜索可匹配名称和地址，并保留祖先上下文。展开/折叠改变展示，不改变变量地址；勾选决定绑定的活动状态。

叶节点刷新频率为 UI 最新值刷新设置。标量写入沿用 ExtendType 的解析和范围校验，硬件写操作经 App/Worker 排队。表格数值调参不修改源码或 ELF。Pop out 使用原生 viewport，配合主窗口 Chart 同时显示；切换插件不终止 Chart 数据摄取。

## 6. 原有 Debug 与采样调度

高层源码信息、调用栈与局部变量由 probe-rs-debug 处理，底层运行/暂停、断点和读写由同一 ProbeWorker 执行。`program_generation`、revision、stop_id 等标识隔离旧映像和旧暂停栈帧结果。

`acquisition_requested` 表示用户的采集意图，实际 `running` 表示是否正在产生 Stream。MCU Running 时进行高速采集；Debug 命中断点或 Halt 后停止 Chart Stream，并维持约 1 Hz Table Latest。Continue 后按原采集意图恢复。源码级单步、硬件断点容量、PRIMASK 临时屏蔽及清理流程见 `ARCHITECTURE.md`。

新版本不包含源码保存、Keil 后台进程、工程/Target 配置和新编译快捷键。原有 F5 是 Debug 继续执行，其上下文限制保持上游行为。

## 7. 配置、日志与资源

配置使用 JSON 保存探针、ELF 路径、变量池和各插件 payload。迁移时需要修正本地路径；配置加载应在停止采集并断开目标后执行。不要假设本地配置在不同固件版本之间地址不变。

CSV 在 `acquisition_requested` 从 false 转 true 时通过 `File::create` 打开，因此再次开始会覆盖原选文件。暂停关闭写入器。Chart 内存历史连续保留与 CSV 文件重新开始是两个不同生命周期，用户说明明确提示分段换文件名。

窗口 PNG 使用 `include_bytes!` 编入程序。Windows 文件资源管理器图标需要额外运行 `tools/set_windows_icon.py` 写入 PE 资源；桌面快捷方式则使用 ICO 路径。该资源修改应在签名之前进行，当前便携程序未做代码签名。

## 8. 验证与维护

纯逻辑/无硬件测试覆盖完整历史、绘图压缩、旧配置默认值、搜索与表格渲染，也覆盖上游 DWARF、调试及其他模块。恢复后执行 Windows GNU Release 测试，结果记录在 CHANGELOG。120000 点回归验证不会在旧容量处丢掉起始点；这不是物理探针长时采样实测。

维护时优先遵循：单一硬件所有者；UI 不阻塞等待 Probe；不把暂停期间的 Latest 数据写进 Chart；绘图压缩不修改原始历史；旧映像/旧栈帧结果不回写新状态；保留 unsafe 块的 SAFETY 说明。

公共仓库只收源码、通用资源和文档。固件、CSV、用户配置、设备标识、编译缓存、本机路径日志和凭据应排除。仓库 `.gitignore` 是防误操作的辅助，发布前仍应检查暂存区。

## 9. 安装与环境检测

`tools/build_installer.py` 从实际 x64 PE 导入表生成依赖清单，`installer/check_runtime.c` 使用仅依赖 Windows 核心 API 的引导器逐项加载系统运行库。通过后启动包内程序的 `--check-install` 入口，`src/install_check.rs` 使用默认 eframe 渲染器初始化隐藏窗口并退出，不创建 MemRW3App 或 ProbeWorker。引导器对渲染进程设 60 秒超时，失败由安装器展示并终止安装。安装脚本为 `installer/MemRW3.iss`。安装前检查只解包到临时目录并写用户检查报告，检测失败不复制应用文件到安装目录。
