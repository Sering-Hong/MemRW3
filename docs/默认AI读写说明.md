# 默认 Codex 读写版 2.2.0

## 使用方式

当前程序（已合入初音静态外观）：`dist/MemRW3/MemRW3.exe`。

**打开程序即自动启动本机Codex接口；全部已加载、类型和大小匹配的数值变量默认可读写。** 不需要开启AI接口，不需要勾选可写参数，不需要设置白名单或授权上下限。原来的AI开关和AI写入设置窗口已移除，顶部只显示“Codex 读写就绪”或接口异常状态。

正常加载调参JSON/AXF，由人工按原流程连接设备并采集后，直接告诉Codex要读取或修改哪个参数、改成多少即可。软件不会自动连接探针或启动电机。读取配置中的变量清单不要求采集；读取实际运行值需要已有采样。

本机memrw3注册已更新到本目录脚本。工具仍是原来的14个，原生工具已加载的聊天可选择新版实例使用同名接口；后续会话使用新注册路径。若新旧程序同时运行，Codex需通过list_sessions确定目标实例，新版server_version为2.2.0。

## 默认访问含义

- get_write_permissions保留作为兼容的变量能力查询，enabled默认true，access_mode为all_loaded_numeric。
- allowed_variables列出全部数值型且实际大小匹配的已加载变量；min/max仅为对应整数/浮点类型可表示的界限，bounds_source为numeric_type_limits，不是人工授权范围。
- 数值写入仍按真实类型编码，拒绝非法数值、溢出、NaN/Inf、未知ID和不匹配的大小。结构体/数组需要使用其中的数值字段，不增加任意地址或整块内存写入工具。
- 默认具备读写能力不等于已经连接设备；断开或忙状态下请求仍会明确失败，不假报成功。

连接、复位、配置/ELF变化时，软件取消旧的在途请求、更新permission_epoch并立即为后续请求保持默认读写。PID旧会话因此需要重新建立基线，但无需重新授权。退出程序时保持旧请求失效。

## 保留的执行检查

写前读取并比较expected_value、写后读回核验、唯一request_key防重发、单一在途、请求截止和明确结果状态仍保留。它们由软件自动处理，不增加人工点击步骤。原生结果为pending时需查询get_write_result，uncertain不能自动换key重试。

普通参数修改可以直接使用write_variable，无需建立PID会话。PID工具继续保留基线、每轮单增益、max_step、观察时间、安全条件和条件回滚；max_step是调参策略，不是写入授权门槛。
