# 通用 PID 在线调试方案

## 1. 当前交付与总体结构

已按“不指定轴、单组PID、每轮只改一个增益”落地主机会话管理。当前程序为 `dist/MemRW3/MemRW3.exe`，桥接脚本为同目录 `tools/memrw3_mcp.py` 与 `tools/pid_online.py`，MCP共14个工具。本机 `memrw3` 注册更新到此版本。默认访问说明见 `默认AI读写说明.md`。

```text
MCU原有控制环 → MemRW3采集/原始历史 → MCP读取 → AI评价与提出候选增益
                                     ↓
已加载变量/数值类型 → PID会话/基线/步长/条件校验 → 受控单值提交 → 写前比较/写后读回
                                     ↓
                       观察响应 → 接受为新基线，或请求回滚上一基线
```

MCU继续承担原来的控制闭环，AI只在主机侧按试验轮次调整增益。没有后台自动写入线程，没有在本轮改动固件、烧录或操作MCU。模型不会因为打开接口就自动运动或开始调参。

**当前没有三增益原子提交、硬实时保护、断网自动回滚、自动阶跃或自动稳定性认证。** 主机会话只完善“读—改—查—评—退”的可追溯流程，快速保护仍需固件及机构承担。

## 2. 数据接口与准备条件

| 数据 | 必需内容 | 当前取得方式 |
| --- | --- | --- |
| 参数 | Kp、Ki、Kd，实际类型/大小、精确值与原始字节 | `list_variables` + `read_variables`，三项必须为Float/Double |
| 运行信号 | 目标r、反馈y、控制输出u | 显式绑定三个变量；实时快照与`get_history`读取 |
| 时序 | 观察时间、年龄、采集相对时间；丢样/间隔评估 | 现有读取字段；观察时间不等于精确硬件采样时间 |
| 运行状态 | 已连接、正在采集、未烧录/切换、未调试暂停 | `get_status` 与批量读取返回的状态 |
| 参数身份 | 软件实例、变量ID/名称/地址/类型/大小 | PID会话绑定并逐次复核；不依赖固定硬编码地址 |
| 默认访问 | 全部已加载数值类型及上下文代次 | `get_write_permissions.permission_epoch` |
| 安全条件 | 故障码、使能/模式、位置/速度/输出边界等 | 最多16条显式guard：变量名、eq/le/ge、十进制值 |
| 试验约束 | 每项最大单轮增益变化、最小间隔、观察时间 | `pid_begin`显式传入max_step；时间参数可配置 |

使用前由人工加载与目标固件一致的AXF/ELF及变量配置，连接并开始原有采集。接口与数值读写默认可用，无需AI开关或逐项授权。get_write_permissions的上下限是数值类型界限，不是业务授权范围。目标值、使能、模式切换、发射触发、软限位和故障清除不属于PID工具的可写角色。

必须由操作者确认Kp/Ki/Kd属于同一控制器、同一环；通用工具不会从名字猜测物理配对。PID工具必须明确绑定六个不同变量：`kp`、`ki`、`kd`、`target`、`feedback`、`output`。不猜测变量名，也不把输出指令当作真实电流或真实执行效果。积分状态、输出限幅、实际电流、电机在线、温度等如果能够采集，应加入观察数据或guard；缺失时标记“需补充信息”。

误差 `e=r-y`；单位必须由接口/固件确认。判断超调、整定时间、稳态误差及振荡，需要把r/y/u添加到Chart并取得足够长的原始时间窗。评价可采用对齐时间后的误差RMS、尾段误差均值、阶跃超调、整定时间与输出饱和占比；目标非恒定阶跃时不要直接套用标准阶跃超调公式。PID快照是顺序读取的观察值，不是同步原子采样帧；历史不保证无丢样，应检查时间间隔及覆盖长度。历史返回truncated时，不把缺失窗口当完整试验。

## 3. 已实现工具和读取/写入流程

| 新工具 | 行为 |
| --- | --- |
| `pid_begin` | 校验在线状态、数值访问及六项绑定，读取三增益原始基线，原子落盘；不写MCU |
| `pid_snapshot` | 查询在途结果，读取三增益、r/y/u和guards；报告是否符合预期增益组合 |
| `pid_apply` | 单轮只提交Kp/Ki/Kd中的一项，校验最大单步、数值类型、原值和上下文代次 |
| `pid_accept` | 满足观察时间且读回组合一致后，根据调用方给出的评价理由更新基线 |
| `pid_rollback` | 验证当前三增益仍为本轮预期组合，仅恢复本轮改动的一项，并再次读回确认 |
| `pid_end` | 关闭已经解决的试验会话，不停止电机、不改参数、不自动恢复初始值 |

原有读取、历史、权限、单值写入和结果查询八个工具继续可用。

一轮执行流程：

1. `pid_begin`给出绑定、三项max_step及guards，取得`tuning_id`。初始基线是操作员选定的起点，不自动视为安全或稳定。
2. `pid_snapshot`结合`get_history`读取数据；核对当前工况、信号单位、目标与故障条件，保存本轮对照窗。
3. AI依据事先约定的评价指标提出一个候选增益。每轮只改一项，不同时改目标、增益、限位或控制模式。
4. `pid_apply`在本地先保存基线和写入意图，再调用现有受控写入。请求含目标值、预期旧值、上下文代次及唯一request_key。
5. 用`pid_snapshot`查询。只有原生结果的完整请求、上下文代次及verified状态与意图一致，才进入`observing`。排队、超时、不确定都不能当成功。
6. 观察足够时间后对照相同工况。认为可接受时调用`pid_accept`并记录依据；否则调用`pid_rollback`，持续查询直到`rolled_back`，再确认三项值。

`pid_accept`只记录AI或人的评价，不自动计算/认证闭环稳定性。评价准则应在试验前确定，例如误差、超调、整定时间、振荡持续时间、饱和占比和位置/速度/电流界限；本轮不为未知对象虚构数值。

尚有未解决试验时不能开始下一次修改。请求键在会话内不得跨apply/rollback或历史轮次复用；原生键还带有tuning_id前缀，防止不同PID会话串单。

## 4. 实时性要求与已设置的时间约束

| 层次 | 建议/已知值 | 边界 |
| --- | --- | --- |
| MCU控制周期 | 由固件固定；RP27当前配置名义1ms | 不让AI参与每个控制周期，不等于实测无抖动1kHz |
| 波形采集 | 可先按50–200Hz评估，最终按关注带宽、探针与样本间隔确定 | 这是建议，不是已配置或测得的采样率；高速内环可能需要更高频本地记录 |
| 软件显示 | 既有周期刷新目标60Hz | 不等于采样率，不是实际帧率保证 |
| AI读取/评价 | 建议每0.5–1秒读取快照，结合数秒历史分析 | 模型/网络无确定性响应期限 |
| 增益更新间隔 | 默认最小1秒，可设0.2–60秒 | 是限制提交频率，不会自动定时修改 |
| 最小观察时间 | 默认2秒，可设0.2–60秒 | 必须根据被控对象实测整定时间调整，2秒不证明稳定 |
| 观察数据年龄 | 默认上限200ms，可设20–1000ms，并要求stale=false | 基于主机观察年龄；不伪称真实MCU采样年龄 |
| 单次请求/写入截止 | 沿用原生2秒截止，过期未执行请求不得延后写 | 超时后先查原key，禁止盲目重发 |

应在实机验收记录读取/写入延迟P50/P95、采样间隔、丢样、GUI最小化/模态窗口阻塞、暂停/断线等情况。目前没有此类实机测量，不承诺“毫秒级AI调参”。

推荐“低频改增益、高频观察原始波形”；快速越限保护、输出限幅、急停、反馈超时和通信失联安全退出应在MCU/硬件中实现，不能等待AI回复。

## 5. 安全校验、基线与回滚

已有和本轮增加的校验：

- 接口和全部已加载数值变量默认可读写，按实际类型检查有限值与大小，不设人工白名单。
- 实际数值类型界限 + 每项max_step + 最小提交间隔；max_step按转换后的实际增益比较，极小浮点边界可能被保守拒绝。
- 比较软件实例、变量身份和permission_epoch；原生提交端也检查预期epoch，避免连接/复位/配置变化后的跨上下文写入。
- 每次执行前复核数据年龄、连接/采集/忙状态及guards。外部修改任一增益后拒绝覆盖，不把读写成功当控制效果合格。
- 先落盘、后提交；文件独占锁防并发；写意图和原生结果逐项匹配，不能把旧apply结果误当回滚成功。
- 原生层写前读取比较，写后读取核验；同key不重复执行；旧上下文失效和截止时间覆盖GUI/worker队列。

回滚分类：

| 情况 | 动作 |
| --- | --- |
| 写前校验失败/原值不符 | 不写入，不需要恢复；重新观察，不覆盖第三方修改 |
| 已verified但效果不满意 | 请求`pid_rollback`恢复上一基线的本轮增益，读回确认后才能称参数恢复 |
| 当前PID被其他人/固件改过 | 拒绝自动覆盖，人工确定新的基线 |
| 写入/读回不确定、结果身份冲突 | 停止推进试验，查询原操作并人工介入；不凭旧值盲写 |
| 断线、停止采集、guards失败 | 主机拒绝新增修改和盲目回滚；由固件/操作员执行对应的安全动作 |
| 重连、复位或换配置 | 旧会话epoch失效，重新建立基线 |

基线与试验记录保存在当前用户应用数据目录 `MemRW3/pid-sessions/`，使用临时文件+fsync+原子替换；保留初始基线、最近接受基线及最多100轮历史。会话锁在进程崩溃后可能保留，必须先核对原生操作结果再人工处理，不能直接删除锁后重发。原生进程最多256个写记录，跨程序重启不保留去重表。

恢复Kp/Ki/Kd并不恢复积分、历史误差、机构位置或储能状态。当前工具不会外部强行清积分；Ki变化可能让已有积分贡献突变。掉电后的参数保留取决于固件，本工具不写Flash。

若后续要求“三项同时生效、无扰切换、断网自动回滚”，应增加固件影子参数/版本提交接口：主机写candidate三项与版本，控制任务在周期边界验证权限和范围后一次接纳；返回applied_version/status并保留previous参数；固件用本地限幅、租约/反馈超时和故障策略决定恢复或安全停止。该接口本轮**未实现**，不能把三个探针写操作视作原子事务。

## 6. RP27源码参考与待补信息

本次同时核对了源码与岗位调试/力闭环笔记，未修改笔记、历史归档或固件，也未核实目标板实际运行版本。

- `Application/ControlLayer/dart_tune.c/.h`：已有单轴速度/位置调参入口，要求测试/手动、有效零点；上膛还要求loader_safe。enable/axis/mode/目标/seq是运动接口，不由本通用PID会话自动写入。
- `Application/ModuleLayer/mech_axis.c/.h`：pos_pid/spd_pid/zero_pid分开；速度调参用spd_pid，位置模式为位置外环+速度内环。zero_pid不作为本轮默认调参对象。
- `Application/AlgorithmLayer/PID.c`：`I=clip(I+e)`，`u=clip(Kp*e+Ki*I+Kd*(e-last_e))`；不是显式带dt的连续PID写法，Ki/Kd不能直接套另一库的数值。
- `Application/TaskLayer/control_task.c`及`dart_config.h`：osDelay按DART_CTRL_PERIOD_MS配置，当前为1ms；周期抖动未实测。
- `dart_tune.h`说明直接改pos_pid/spd_pid属于RAM调试，掉电恢复配置值；PID参数读取/改写本身不代表调参接管条件已经满足。

通用使用前仍需补充：所调对象/环、r/y/u单位、实际控制与采样周期、已确认可运行的基线、K值范围和max_step、安全guards、评价阈值、观察时长及异常时真实机构安全动作。上膛/变力/Yaw行程和速度继续按人工实测确定，本轮不推断。
