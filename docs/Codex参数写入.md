# Codex 参数写入

当前使用2.2.0默认读写版，无需下文历史版本的开关/授权步骤；见 [默认AI读写说明](默认AI读写说明.md)。

本页记录基础单值读写版；通用PID会话、最新发布目录和实时性/回滚说明见 [PID在线调试方案](PID在线调试方案.md)。

## 交付与使用

当前读写版：`dist/MemRW3-ai-enabled/MemRW3.exe`，窗口标题为“MemRW3 - AI 参数调试”。原安装版和先前只读程序保留。本机 Codex 的 `memrw3` 注册已更新到该目录的桥接脚本；重启 Codex 后加载新增写入工具。

操作顺序：

1. 打开新版，加载原调参 JSON；由人工按原流程连接目标。
2. 勾选顶部“AI接口”，打开“AI写入设置”。
3. 搜索并勾选允许 AI 修改的参数，填写该参数合法的下限和上限。上下限必须由人工结合机构、固件和调参目标确认，本轮不预设电机行程、速度或 PID 范围。
4. 最后勾选“允许AI写入选中的参数”。之后可直接要求 Codex 修改指定参数，正常写入无需逐次点击软件按钮。
5. Codex 应先读权限和当前值，再提交目标值，并查询最终读回结果；“已排队”不表示写入成功。

重新连接、复位（包括 Debug Reset）、更换配置/ELF、烧录、断开或关闭 AI 接口时撤销权限；退出程序在 worker 关闭前撤销在途写入许可。需要时重新授权。命令行 `--ai-interface`（兼容 `--ai-readonly`）只启动接口，不能打开写入权限。

原只读程序如果仍在运行，可在保存自己的工作后手动关闭；多实例时 Codex 必须先 `list_sessions` 并明确指定 `session_id`，选择 `supports_guarded_write=true` 的新版。

## 工具和流程

| MCP 工具 | 行为 |
| --- | --- |
| `get_write_permissions` | 查询人工授权的变量、类型、上下限及总开关 |
| `write_variable` | 提交单个数值参数修改，返回请求记录 |
| `get_write_result` | 根据 `request_key` 查询最终结果 |

原来的五个读取工具继续保留；总计八个工具。`write_variable` 明确标记为非只读、可能改变设备状态；没有连接探针、暂停、复位、烧录或任意地址写入工具。

写入参数：`variable_id` 为软件内已加载变量 ID；`value` 和 `expected_value` 都是十进制字符串，分别表示目标值和预期旧值；`request_key` 是本次动作的唯一标识，只允许字母、数字、点、下划线和短横线，最长128字符。`session_id` 用于多实例选择。

软件按变量池解析地址和类型，只允许大小匹配的整数/浮点标量，拒绝结构体、类型越界、空范围、范围反向、NaN/Inf 和超出人工范围的目标值。整数比较不经过 f64，保留64位整数精度。

请求进入既有唯一 ProbeWorker，按“读取当前值 → 按位比较预期旧值 → 写入 → 再读取比较”执行，不插入 MCU 暂停或复位。比较不是 MCU 原子 CAS；固件仍可能在这些步骤之间更新变量。读回一致只证明该次读取与目标值一致。

## 结果、重试与记录

- `pending`：已提交，需继续查询。
- `verified`：写入后立即读回一致；结果含类型、请求值、写前值和读回值。
- `rejected`：比较、权限或时限等检查拒绝，未调用写入。
- `not_submitted`：未成功送到 worker，未执行此请求。
- `uncertain`：尝试过写入，但总线写入失败、读回失败或读回不同；可能已经影响目标，不允许自动换新 key 重试。

相同 key 和相同参数在本次进程只返回原记录，不再次提交；同 key 更换参数会拒绝。一个时刻只允许一项在途 AI 写入；最多保留256个操作记录，达到上限后拒绝新增请求，记录在退出程序后不保留。跨重启无法仅凭旧 key 确认以前是否写过，必须重新读取并由人工判断。

网络请求和 worker 执行共享截止时间；超时后仍在 GUI 队列或 worker 队列的请求不会延迟写入。已经完成的写入无法通过关闭权限撤销。收到超时也应先查原 key 的结果，不能直接重发。

本工具执行目标内存写入，不增加参数持久化功能；重启后是否保留由固件决定。AI 不根据变量名称猜测硬件安全范围；读取中文注释可辅助理解，但不能替代授权上下限。
